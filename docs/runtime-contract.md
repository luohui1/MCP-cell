# MCP-cell Runtime Contract · v0alpha1 提案

本文是 MCP-cell 的设计提案，不是 MCP 官方标准，也不是已经实现的执行能力。

## 两类适配器，避免混淆

ClientAdapter 负责发现某个 AI 客户端的配置、读取与保留原生语义、生成可审查迁移方案。ExecutionAdapter 负责在已批准的资源/安全环境里执行工具。两者必须分离：Claude/Cursor/Codex 是配置来源；MCP stdio、MCP HTTP、CLI argv 才是执行接口。

本版已实现前者的只读子集，ExecutionAdapter 尚未实现。前端使用归一化清单和显式 capability 状态，不依赖具体执行协议。

## 对象模型

SourceRecord：客户端、文件、格式、作用域、工作区、源版本及读取错误。

ToolDefinition：来源引用、制品身份、适配器类型、参数模式、原生语义版本。命令或工具名相同不等于身份相同。

PolicyBinding：用户批准的文件范围、网络出口、凭据引用、审批规则、资源预算和实例共享分区。服务声明只能申请权限，不能自行授予。

CellInstance：固定制品版本与策略下的受控进程树或远程连接单元。实例状态及实际生效约束必须可查询。

Lease：调用者、工作区、授权域、生命周期及业务状态归属。内部租约不修改 MCP 外部协议。

OperationRecord：请求归属、批准参数摘要、策略与制品版本、执行结果、清理结果以及预算消耗；默认不保存明文参数和工具输出。

## MCP 与 CLI 统一执行约束

`adapter.kind` 可为 `mcp-stdio`、`mcp-http`、`cli-argv`。所有形式共用主体、工作区、权限、预算、审批及审计。CLI 必须使用显式 argv 与参数模式，不从模型文本拼接 shell，不把命令名相同当作相同制品，不通过任意 `--help` 发现工具。

MCP 传输版本和能力须单独协商或识别；不根据 URL 推断完整协议语义。旧版会话、服务端请求、订阅和新版显式状态均需专门测试。此 discovery 原型不进行消息转发，所以不宣称协议层互通。

共享默认禁止。最先实现独占、按需启动及可靠回收，再开放通过验证的复用配置。共享分区至少覆盖制品摘要、启动配置、身份/凭据授权域、工作区/挂载、策略版本及状态模型。不能通过合并权限提升复用率。

操作超时或取消不等于业务回滚；写操作响应丢失应允许报告 `outcome_unknown`。未经幂等性和去重证明，不自动重试。

## 生命周期与资源

建议状态：registered → stopped → starting → ready → draining → cleaning → stopped。失败进入 cleaning；只有清理成功才允许有预算的退避重试，清理失败进入 quarantined。

预算必须覆盖管理器、队列/缓冲、实例和进程树。应有全局准入、实例限制、并发/输出字节上限。Windows Job Objects 与 Linux cgroups 的实际计量语义不可混写，未支持的强制约束必须拒绝或明确降级并获批准。

共享 Cell 可以提供请求级调度限制，但不能凭一个进程的内核限额声称每个请求都有独立硬内存隔离。需要强隔离的任务应使用独立执行单元。

## 自动规范化与迁移流程

1. 发现：只读已批准路径，保留全部来源和未解释字段。
2. 核对：识别最终作用域、工作区信任、审批/工具白名单、环境与输入变量、传输版本。无法解释即阻断。
3. 生成方案：保持原工具身份，预览每个来源的无损配置补丁。候选去重不是共享批准。
4. 备份：每个源文件的字节级快照、权限/ACL、原始版本和变更清单。
5. 应用：逐源前置版本核验、同目录暂存、持久化、原子替换；跨文件不假定有天然原子性，需事务日志与恢复策略。
6. 验证：新客户端实际连接与受控工具 smoke probe；明确哪些能力未验证。
7. 回滚：只在当前文件仍等于本次写入版本时恢复；客户端又改过则报告冲突，不覆盖用户新改动。

以上迁移尚未实现。本版 `/api/plan` 仅输出 operation=review-before-enrollment、applicable=false 和阻断项，不生成可执行补丁。当前源版本是进程内 HMAC，跨进程持续迁移需独立的受保护版本机制。

## 前端事实约束

`discovered`、`configured`、`approved`、`managed`、`running`、`enforced` 必须区分。文件存在不能显示为“运行中”。进程未采样、基线未测量时，进程数和内存节省为空。

展示“实际生效”的操作系统资源机制、策略状态、失败原因和未覆盖项。不得用装饰性开关代替执行后端，不得在发现阶段提供“安全共享”绿色认证。

## 实施顺序

P0（本版）：只读配置适配器、来源清单、候选发现、审查提案、液态简洁控制台、回归测试。

P1：优先 Codex/Claude Code/Cursor 的无损事务迁移与恢复测试；不会扩大原客户端权限。

P2：独占 MCP 执行、轻桥与管理器、进程树回收、实际资源测量、Windows/Linux 后端。

P3：限定服务版本与安全域的复用验证；故障注入和并发压力测试。

P4：显式注册 CLI 适配器；不开放任意 shell。
